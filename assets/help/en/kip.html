KIP — app-like command interfaces

KIP (Kai Interface Protocol) lets a command turn the output panel into a small app: instead of text, Kai shows forms, confirmations, lists, tables, progress bars, checklists and a result card with buttons. The program only prints JSON lines; Kai draws the interface.

It fits wizards (deploy, restore, scaffolding, onboarding), logins that export a token, file conversion and lookups with a result table.

1. Turning it on

Open the command editor, KIP tab (command-type commands only, not HTTP), and tick KIP interface (or set kip: true in the file). Open in its own window (kip_window: true) shows the view in a separate window. Close the window when it finishes (kip_auto_close: true, with an optional delay in seconds) closes that window by itself after a successful run — made for quick scripts started with kai -gw; a failure or a cancel keeps it open so you can read the error.

  • Kai never changes your command. If the tool needs a flag (mytool deploy --kip), write it in the command.
  • The parameters form still runs first, and {{VAR}} works in the command.
  • Kai sets KIP_VERSION=1 and KIP_LOCALE (en/pt) in the program's environment.
  • Background, interactive terminal, formatted output, Markdown, auto-run, schedule, auto-replies and export-from-environment are disabled for KIP commands, and a KIP command can't be used as a hook.

2. How the program talks to Kai

stdoutmessages to Kai, one JSON object per line: {"kip":1,"type":"..."}
stdinKai's answers: response, change, back, cancel
stderrfree log, shown in Details → Log

The first message must be hello. If the process exits (or 10 seconds pass) before it, Kai shows "This command doesn't support KIP". Stdout lines that aren't protocol go to the log.

hellohandshake; names the app
promptform with fields; wait for the answer
confirmyes/no (danger for destructive actions)
patch / invalidupdate fields while open / reject an answer with messages per field
message, markdownstatus card, formatted text
progress, steps + stepbar (or indeterminate), live checklist
tableread-only table (select a cell and press Ctrl+C)
notifysystem notification
set_envexports a declared variable
chip_resultprogress and outcome of a chip (see below)
doneresult screen with buttons: open URL (http/https), reveal in the file manager, copy

3. Field types

text, secret, textarea, number, date, select, list, table, filepick, folderpick and flags. Fields can be required, have a default, belong to a group and be watched: when the user changes a watched field Kai sends change and the program answers with a patch (this is how a second list depends on the first). Kai remembers the last answers of each prompt (never secret); turn it off with remember: false.

4. Chips and long lists

Chips are small buttons under the fields of a prompt for ephemeral actions — "show the context of this branch", "sync", "delete". Clicking one does not answer the form: Kai sends chip to the program, which replies with chip_result messages (running, then success or error, with a Markdown text) shown in a box under the chips. The step stays open and an error never ends the session.

  • A chip can ask for confirmation first (confirm, inside the box) and look destructive (danger).
  • requires keeps the chip disabled until the listed fields are filled.
  • One chip runs at a time; close the box with the × button.

For list and table fields, searchable forces (or hides) the filter box and page_size splits the items into pages with a "Page 2 of 5" bar. Pages apply to the filtered result and keep what you selected.

5. The kai kip helper

You don't need to write JSON by hand in shell scripts:

kai kip hello --title "Deploy"
kai kip prompt --id env --title "Where to?" \
  --field select env "Environment" --options dev,staging,prod --required
read -r resp
[ "$(kai kip get "$resp" type)" = cancel ] && exit 130
env=$(kai kip get "$resp" values.env)
kai kip progress 50 "Uploading..."
kai kip done --title "Deployed" --action open_url:"Open":https://example.com

It only prints messages and reads values: it needs no running app. kai kip --help lists every verb and option.

Python, Node and PHP, no file: set the command's Language to Python, Node or PHP and turn KIP on — the command text is the program, and Kai injects a kip module (import kip in Python; the global kip in Node, with top-level await; the class Kip in PHP):

import kip
v = kip.prompt([{"name": "env", "type": "select", "options": ["dev", "prod"]}],
               id="where", title="Where to?")
kip.progress(50, "Deploying...")
kip.done(title="Deployed to " + v["env"])
$v = Kip::prompt([['name' => 'env', 'type' => 'select', 'options' => ['dev', 'prod']]],
                 ['id' => 'where', 'title' => 'Where to?']);
Kip::progress(50, 'Deploying...');
Kip::done('Deployed to ' . $v['env']);

hello is sent for you, output is unbuffered, Cancel exits with code 130 and Back raises kip.Back (KipBack in PHP). {{VAR}} is not replaced in this code; variables come from os.environ / process.env / getenv(). Your own script files (python3 tool.py in a Native command with KIP on) find the module too — see Languages.

5b. kip in the shell

Turn KIP on in a Native command that runs in a POSIX shell (Linux, macOS, WSL, other POSIX profiles): Kai defines a kip function with the same verbs as kai kip — no kai binary needed, so it works in WSL, containers and SSH. hello is sent for you, and {{VAR}} is replaced as in any native command.

kip prompt --id where --title "Where to?" --field select env Environment --options dev,staging,prod --required
kip recv                          # the answer lands in $KIP_MSG (Cancel exits with 130)
target=$(kip get "$KIP_MSG" values.env)
kip progress 50 "Deploying..."
kip done --title "Deployed to $target"

Limits:

  • The helper is POSIX sh + awk (mawk, gawk and busybox work); the inline form also needs base64 and gzip. No jq.
  • Use kip recv in the main script, not inside $( ), or the answer is lost with the subshell; don't reuse the _kip_* names.
  • kip raw only checks the basic shape of the message; kip get prints exponent numbers as written and drops NUL bytes. Helper messages are in English.
  • Windows without a POSIX profile (plain cmd.exe / PowerShell) has no kip function: use a WSL profile, or write the program in Python, Node or PHP. A text too long for the command line is written by Kai to a file of its own and loaded from there (shell, Python, Node and PHP alike).

6. Exporting variables

A program can set a dynamic variable with set_env only for names listed in the command's Exportable variables tab. The value is immediately available to other commands as {{NAME}}.

7. The view

  • One screen at a time, with a summary of your previous answers above it (secrets appear as ••••).
  • Back appears when the program allows it; Cancel run asks the program to stop (and stops it after 3 seconds).
  • A destructive confirmation focuses the decline button, so Enter never confirms by accident.
  • Details (collapsed): the Log and the Protocol inspector with every message in both directions.
  • The output panel's tab bar is hidden for KIP commands; the icon at the top-right of the view opens it in its own window.
  • Failures, cancellation, unsupported and protocol errors show a card with the details open and Run again.

8. Settings and the creation manifesto

Settings → KIP has the global preferences: how long to wait for the program's first message, for the answer to a field update and after Cancel; whether to remember the last answers; and whether the Details drawer opens by itself on failures; and the Own-window size — follow the general window setting, normal, maximized or fullscreen (it applies to KIP views only). Whether a command uses KIP is set in its own editor (command-type commands only, not HTTP).

Help → Creation manifesto copies, with one click, the guide to hand to an AI assistant so it writes a KIP program (or a kai.yml) for you.

9. In the terminal

kai -g <command> runs a KIP command in the app and brings its view to the front. With -w (or kip_window) the view opens in its own window and the main window is not shown. In local mode (kai inside a folder with a kai.yml) KIP commands are refused: there is no interface to draw them.
