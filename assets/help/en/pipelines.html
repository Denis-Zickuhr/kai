Pipelines

A pipeline is a command whose body is a list of steps. Each step runs another command of yours, with optional checks, questions, retries and decisions. The run is one guided screen: a checklist with a live log per step.

Pick Pipeline as the type in the command editor and add steps in the Steps tab. A pipeline never starts by itself: no schedule, no auto-run.

What a step does

  • Run — the command, by name or Folder/Name. It can be a KIP command: its screen takes over while it runs.
  • Check — a command whose exit 0 means "already done": the step is skipped as Already ok, and verified again after the run.
  • Confirm and Ask — a question before the step; answers are {{ask.name}}. Secret answers are masked.
  • When — conditions; false skips the step.
  • Wait until — polls a command until it exits 0, or times out.
  • Capture — reads values from the output: NAME: stdout:regex, json:path, exit, status.

When a step fails

Retries run it again (optionally asking again). Then On failure decides: abort, continue, ask (Try again / Skip / Abort) or goto:<step id> to jump forward, e.g. to a rollback.

- name: "Ship"
  type: "pipeline"
  steps:
    - id: build
      run: "steps/build"
      check: "steps/is-built"
    - id: health
      run: "steps/noop"
      wait_until: { check: "steps/health", timeout: 60 }
      on_fail: "goto:rollback"
    - id: rollback
      run: "steps/rollback"
      when:
        - { left: "{{steps.health.ok}}", op: "eq", right: "false" }
Put the step commands in a subfolder and mark them Hidden. Every step leaves {{steps.<id>.ok}} and {{steps.<id>.exit}}.

Running

  • Stop ends the current step for real and the run is cancelled.
  • When a run ends, right-click a step and choose Run from here to resume it, keeping the captured values.
  • From the terminal: kai -g <path>, with --from <step> or --only <step>.
