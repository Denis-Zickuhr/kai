Pipelines

Uma pipeline é um comando cujo corpo é uma lista de passos. Cada passo roda outro comando seu, com verificações, perguntas, novas tentativas e decisões opcionais. A execução é uma tela guiada: um checklist com log ao vivo por passo.

Escolha Pipeline como tipo no editor do comando e adicione os passos na aba Passos. Uma pipeline nunca começa sozinha: sem agendamento, sem auto-run.

O que um passo faz

  • Executar — o comando, por nome ou Pasta/Nome. Pode ser um comando KIP: a tela dele assume enquanto roda.
  • Verificar — um comando cuja saída 0 significa "já feito": o passo é pulado como Já está ok e conferido de novo após a execução.
  • Confirmar e Perguntar — uma pergunta antes do passo; as respostas são {{ask.nome}}. Respostas secretas são mascaradas.
  • Quando — condições; falso pula o passo.
  • Aguardar até — repete um comando até sair 0, ou estourar o tempo.
  • Capturar — lê valores da saída: NOME: stdout:regex, json:caminho, exit, status.

Quando um passo falha

Tentativas extras repetem o passo (podendo perguntar de novo). Depois Ao falhar decide: abort, continue, ask (Tentar de novo / Pular / Abortar) ou goto:<id do passo> para pular para frente, por exemplo até um rollback.

- name: "Ship"
  type: "pipeline"
  steps:
    - id: build
      run: "steps/build"
      check: "steps/is-built"
    - id: health
      run: "steps/noop"
      wait_until: { check: "steps/health", timeout: 60 }
      on_fail: "goto:rollback"
    - id: rollback
      run: "steps/rollback"
      when:
        - { left: "{{steps.health.ok}}", op: "eq", right: "false" }
Coloque os comandos dos passos numa subpasta e marque-os como Ocultos. Todo passo deixa {{steps.<id>.ok}} e {{steps.<id>.exit}}.

Executando

  • Parar encerra o passo atual de verdade e a execução fica cancelada.
  • Quando a execução termina, clique com o botão direito num passo e escolha Rodar daqui para retomar, mantendo os valores capturados.
  • Pelo terminal: kai -g <caminho>, com --from <passo> ou --only <passo>.
