HTTP Commands

An HTTP command makes a request and shows the formatted response. In the editor it has four pages: General (method, URL, body), Request (headers, query parameters, authentication), Connection and Response (extractors, assertions, save to file).

Method and URL

GET, POST, PUT, PATCH, DELETE, QUERY, HEAD and OPTIONS are in the list; the field is editable, so any other verb (PROPFIND…) can be typed. The URL accepts variables: {{BASE_URL}}/users.

Headers, query and authentication

Headers and query parameters are tables; each row has a checkbox to turn it off without deleting it. Authentication is a choice: Basic, Bearer token, API key (header or query), None or Inherit from the folders. Use a variable marked Secret ({{API_TOKEN}}) instead of typing a token. An Authorization header written by hand always wins.

Share headers with a folder

A folder's HTTP tab holds headers, authentication and connection options that every HTTP command in it and in its subfolders inherits. A header with the same name set closer to the command replaces the inherited one; in the command's Request page the inherited headers are listed with their folder — untick one to turn it off for that command.

Body

JSON / XMLthe text with the matching Content-Type; JSON has a validity check and a Format button

Connection

Redirects (followed by default, the chain is shown in the Request tab), TLS verification, proxy (system reads HTTPS_PROXY/HTTP_PROXY/NO_PROXY, or none, or a URL), timeout (off by default: Enable it to limit this request or folder only; while a request waits the output shows the elapsed time and whether there is a timeout) and the cookie jar. With no response at all (timeout, refused connection) the Request tab opens with the reason. Cookies live in memory while Kai is open and are shared by all requests; File → Clear HTTP cookies empties them. Every option can stay on Inherit.

Response

JSON is a collapsible tree (Copy, Pop out); XML is indented; images, PDFs and other binary content get a Content tab with a preview and a Save to file… button. The Request tab shows what was sent, the redirects and the time to the first byte; Headers shows the response headers.

Extract a value into a variable

Configure an extractor to grab a field from the JSON response into a dynamic variable (e.g. data.token → AUTH_TOKEN), used by the following commands: Authorization: Bearer {{AUTH_TOKEN}}.

Assertions

Checks on the response, in the same format as execution conditions: {{RESPONSE_STATUS}} equals 201. When any is on, they decide success (so a 404 can be expected). Variables: RESPONSE_STATUS, RESPONSE_TIME_MS, RESPONSE_SIZE, RESPONSE_CONTENT_TYPE, RESPONSE_BODY, RESPONSE_HEADER_<NAME> and your extracted variables. They stay available to the next commands and hooks.

Save the response to a file

On the Response page, give a path: successful (2xx) responses are written to it as they arrive instead of being kept in memory.

Stop and event streams

The Stop button cancels a request in flight. A text/event-stream response (Server-Sent Events) is shown as the events arrive and runs until the server closes it or you press Stop; raise the Timeout (it counts the time without data) for slow streams.

Quick edit

The Quick edit button (side bar or shortcut) opens method, URL, body, query, headers and authentication without the full editor. New HTTP commands start with Content-Type and Accept: application/json and a JSON body; Host is sent automatically from the URL.

Copy as cURL or code

The Copy as… button copies the request as cURL, Python (requests) or JavaScript (fetch), with the variables resolved. The opposite direction: cURL Import.

Example

- name: "Create user"
  type: "http"
  http_config:
    method: "POST"
    url: "{{BASE_URL}}/users"
    auth:
      type: "bearer"
      token: "{{API_TOKEN}}"
    body_type: "json"
    body: "{\"name\": \"{{NAME}}\"}"
    env_extractors:
      - json_path: "id"
        env_var: "USER_ID"
    assertions:
      - left: "{{RESPONSE_STATUS}}"
        op: "eq"
        right: "201"
