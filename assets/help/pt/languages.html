Python e Node

O texto de um comando pode ser código em vez de uma linha de shell. Escolha a Linguagem no canto superior direito do campo do comando: Nativa (shell) (o padrão), Python ou Node. Sem python3 -c "...", sem heredoc: você escreve o código, o Kai monta a chamada.

import os
for f in os.listdir('.'):
    print(f, os.path.getsize(f))

Como roda

O Kai entrega o código ao interpretador codificado, então não há problema de aspas (qualquer aspa, $, crase ou quebra de linha funciona) e o stdin continua livre: o input() funciona e o KIP também. A chamada é só mais uma linha de shell, então passa pelos perfis de execução, como o WSL.

  • A saída do Python é sem buffer e em UTF-8 — não há flush para esquecer.
  • O código Node roda dentro de uma função async: await no topo funciona e return encerra o script. Um erro não tratado sai com código 1.
  • O código de saída decide o sucesso como sempre (sys.exit(3), process.exitCode = 3).

Variáveis e parâmetros

O {{VAR}} colide com código de verdade (f"{{x}}", dicionários, template strings do JS), então o código Python/Node nunca é interpolado. Variáveis e parâmetros chegam como variáveis de ambiente, com a precedência de sempre:

import os
print("Publicando em", os.environ["TARGET"])
console.log("Publicando em", process.env.TARGET);

Qual interpretador

  • Configurações → Linguagens guarda os globais: python3 e node por padrão (no Windows sem perfil de execução, o padrão do Python é python).
  • Um comando pode sobrepor no campo Interpretador.
  • O valor é uma linha de shell resolvida onde o comando roda: num perfil WSL vale o python3 do WSL, e o login shell já carrega pyenv e nvm. Aceita argumentos (uv run python); caminhos com espaço vão entre aspas, por sua conta.

O módulo kai: falar com o app

Todo comando Python/Node tem um módulo kai injetado (nada a instalar) — as mesmas coisas que a CLI kai faz:

import kai
kai.notify("Backup concluído", title="Backup", level="info")   # notificação na bandeja + histórico
kai.commands()              # nomes dos comandos registrados
kai.env.list(); kai.env.active(); kai.env.use("Prod")
kai.run("Deploy")           # dispara outro comando (sem esperar)
kai.ps(); kai.kill("api")   # processos rastreados: {id, name, pid, status}
kai.show()                  # traz a janela para frente
kai.import_project("/caminho/do/kai.json")
await kai.notify('Backup concluído', { title: 'Backup', level: 'info' });
console.log(await kai.commands(), await kai.env.active());
await kai.env.use('Prod');
await kai.run('Deploy');

No Node, kai é um global (e require('kai')) e toda chamada devolve uma promise. Falhas levantam kai.Error. O Kai exporta KAI_IPC_SOCKET; quando o socket não é alcançável (script no WSL sob um Kai do Windows) o módulo cai para a CLI kai em notify, show, run, env.use e kill.

O módulo kip: transformar o comando num app

Com o KIP ligado, o texto do comando é o programa inteiro e um módulo kip também é injetado (import kip; no Node o global kip):

import kip
v = kip.prompt([{"name": "env", "type": "select", "options": ["dev", "prod"]}],
               id="where", title="Para onde?")
kip.progress(50, "Publicando...")
kip.done(title="Publicado em " + v["env"])

Voltar levanta kip.Back, Cancelar sai com código 130, o hello é enviado por você. Referência completa em KIP.

Limites

Exportar variáveis não se aplica (não existe export): use o set_env do KIP. O resto — background, hooks, condições, perfis, agendamentos — funciona como em qualquer comando.
