Shell Commands

A Shell command runs a line (or script) in your shell.

How to create

Menu Item → New command, Shell tab. Fill in the command and, optionally, the working directory.

npm run dev

Variables

Use {{VAR}} to interpolate variables from the active environment:

echo "Starting on port {{PORT}} ({{NODE_ENV}})"

Background

Check Run in background for long-running processes (e.g. a dev server). Kai keeps the process alive and shows its status; stop it whenever you want.

Interactive commands using read accept input directly in the output panel's input field.

Interactive terminal (advanced settings)

For full-screen apps that draw with a cursor — vim, htop, less, a nested Claude Code — turn on Interactive terminal (TUI). The output becomes a real terminal grid instead of a plain-text log, so redraws, colors and keyboard input all behave like a real terminal:

htop

Ignore exit code (advanced settings)

Some tools return a non-zero exit code even when they worked fine — the classic case is explorer.exe called from WSL to open a folder in Windows. Turn on Ignore exit code and Kai always treats the command as a success; a real process crash (signal/segfault) is still reported normally:

explorer.exe .

Hide Kai while running (advanced settings)

For a command that opens another app or window and Kai would just be in the way — e.g. a code editor:

code .

Terminal targets (WSL, containers, ...)

Pick a target under Terminal Target to run the command through a wrapper — see Terminal Targets & WSL.
