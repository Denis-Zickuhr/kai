kai.json file (per project)

Place a kai.json at the project root and import it via File → Import..., picking "Project folder...". Kai creates a folder with its commands, collections and variables.

Minimal example

{
  "project_name": "My Project",
  "env_vars": { "PORT": "8080" },
  "commands": [
    { "name": "Dev Server", "type": "shell", "command": "npm run dev", "is_background": true }
  ]
}

Folders

Nest a command or collection into a subfolder with folder — use / to nest deeper (there's no separate "folders" section; subfolders are created on demand):

{ "name": "Deploy", "type": "shell", "folder": "Integrations/Shopee", "command": "./deploy.sh shopee" }

HTTP command

{
  "name": "Authenticate",
  "type": "http",
  "http_config": {
    "method": "POST",
    "url": "{{BASE_URL}}/auth/login",
    "headers": { "Content-Type": "application/json" },
    "body": "{\"user\":\"{{USER}}\",\"pass\":\"{{PASS}}\"}",
    "env_extractors": [ { "json_path": "token", "env_var": "AUTH_TOKEN" } ]
  }
}

Every command flag, one example each

hidden — stays out of the tree until "Show hidden" is on:

{ "name": "Internal helper", "type": "shell", "command": "./helper.sh", "hidden": true }

hide_on_run — hides the Kai window while this command runs:

{ "name": "Open editor", "type": "shell", "command": "code .", "hide_on_run": true }

capture_env — when used as a hook, captures the environment it exports as dynamic variables (e.g. a login that exports a token):

{ "name": "gh auth login", "type": "shell", "command": "gh auth login", "capture_env": true }

open_last_link — opens the last http(s):// URL printed in the output once the command succeeds:

{ "name": "Start tunnel", "type": "shell", "command": "ngrok http 3000", "open_last_link": true }

interactive_terminal — renders a real terminal instead of a plain-text log, for full-screen apps:

{ "name": "htop", "type": "shell", "command": "htop", "interactive_terminal": true }

terminal_target — runs the command through a named Terminal Target (Settings → Terminal Targets), e.g. inside WSL:

{ "name": "List files (WSL)", "type": "shell", "command": "ls -la", "terminal_target": "WSL" }

compact_output — collapses repeated blank lines and trims trailing whitespace:

{ "name": "Verbose build", "type": "shell", "command": "make -j4", "compact_output": true }

ignore_exit_code — always treats the command as successful, for tools that return non-zero on success (e.g. explorer.exe from WSL):

{ "name": "Open folder", "type": "shell", "command": "explorer.exe .", "ignore_exit_code": true }

auto_run / auto_run_delay_sec — fires automatically when Kai starts:

{ "name": "Start background sync", "type": "shell", "command": "./sync.sh", "is_background": true, "auto_run": true, "auto_run_delay_sec": 5 }

Auto-responders

Answer an output prompt automatically (regex → text sent to stdin):

{
  "name": "Reset DB",
  "type": "shell",
  "command": "npm run db:reset",
  "responders": [ { "name": "Confirm", "pattern": "\\[y/N\\]", "response": "y" } ]
}

Execution conditions

Only run when a guard passes — here, only if TOKEN is empty or EXPIRES_AT is in the past:

{
  "name": "Login",
  "type": "shell",
  "command": "gh auth login",
  "execution_conditions": [
    { "name": "Token missing", "left": "{{TOKEN}}", "op": "not_exists" },
    { "name": "Token expired", "left": "{{EXPIRES_AT}}", "op": "lt", "right": "{{$timestamp}}" }
  ],
  "condition_combinator": "or"
}

Hooks

Reference other commands in the same file by name — pre/post run before/after the main command, cleanup always runs (success, failure, manual stop, or reset):

{
  "name": "Dev Server",
  "type": "shell",
  "command": "npm run dev",
  "is_background": true,
  "hooks": { "pre": ["Login"], "post": [], "cleanup": ["Stop tunnel"] }
}

Collections

A tabular data source, versioned alongside the project, referenced by a select parameter by name:

{
  "commands": [{
    "name": "Greet", "type": "shell", "command": "echo {{customer.value}}",
    "params": [{ "name": "customer", "type": "select", "collection": "Customers", "collection_display_field": "value" }]
  }],
  "collections": [{
    "name": "Customers",
    "schema": [ { "name": "key", "label": "ID", "type": "key" }, { "name": "value", "label": "Name", "type": "value" } ],
    "entries": [ { "values": { "key": "1", "value": "Alice" }, "favorite": true } ]
  }]
}

No kai.json yet?

Turn on "Detect generic definitions" in the Import Project dialog — Kai recognizes package.json, docker-compose.yml, requirements.txt/pyproject.toml/manage.py, composer.json and a Makefile, suggesting ready-made commands from them.

Full field reference, every parameter type, and a generator checklist for AI models: docs/manifesto/kai-json-manifesto.md in the repository.
