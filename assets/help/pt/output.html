O painel de Saída

O painel mostra, ao vivo, o que o comando selecionado imprimiu. Fica embaixo por padrão; Configurações → Layout pode movê-lo para a esquerda ou a direita.

A barra de saídas

Acima do painel há uma barra com uma guia por comando executado nesta sessão — os que ainda rodam e os que já terminaram — para você pular entre as saídas sem caçar o comando na árvore. Uma ação de pasta tem a guia dela por pasta ("Comando · Pasta"). A barra está sempre lá (vazia, mostra uma dica) e só some enquanto o painel está colapsado.

  • Cada guia mostra um ponto de status (rodando, aguardando sua resposta num comando KIP, concluído, falhou, pulado), o nome, o tempo decorrido enquanto roda e um pontinho quando chegou saída nova numa guia que você não está vendo. Passe o mouse para ver os detalhes.
  • Clique numa guia para trazer aquela saída: o comando também é selecionado na árvore (trocando para a pasta raiz certa se ele estiver em outro projeto).
  • Feche uma guia com o × (aparece na guia em foco e ao passar o mouse) ou com o clique do meio. Isso fecha só a guia: o comando continua rodando e o log é mantido. Clique no comando na árvore (ou rode-o de novo) e a guia volta. Fechar a guia em foco passa para a vizinha; fechar a última esvazia o painel.
  • Botão direito abre o menu da guia — Parar, Executar de novo, Mostrar na árvore de comandos, Fechar saída, Fechar as outras saídas, Fechar saídas concluídas — seguido do menu de saída de sempre (limpar, copiar tudo, exportar, opções de exibição). O botão direito não traz a guia para a frente: o menu age sobre a guia clicada (limpar, copiar e exportar usam o log dela) enquanto você continua olhando a sua saída; só Mostrar na árvore de comandos troca para ela.
  • Muitas guias: a roda do mouse rola a barra e um botão no fim dela lista todas.
  • Teclado: Ctrl+Tab e Ctrl+Shift+Tab vão para a próxima / anterior saída (reatribuíveis em Configurações → Atalhos).

As guias não são salvas: começam vazias na próxima abertura, como os próprios processos.

Abas

  • Saída — o stdout/stderr do comando, com cores ANSI.
  • Em comandos HTTP também Resposta (uma árvore JSON navegável), Headers e Requisição (exatamente o que foi enviado) — veja Comandos HTTP.
  • Comandos KIP trocam as abas pela tela própria deles.

O cabeçalho mostra o comando e o estado: parado, rodando, concluído ou erro.

Responder um comando em execução

O campo embaixo envia texto para a entrada do comando — para prompts de read, confirmações, um REPL. Clique nele ou aperte Ctrl+' para focar (e de novo para voltar à árvore). As auto-respostas podem fazer isso por você.

Busca e opções de exibição

  • Buscar na saída (lupa) procura texto no log.
  • O menu de opções de exibição tem: Rolagem automática, Números de linha, Timestamps, Quebrar linhas longas (só visual), Saída compacta (colapsa linhas em branco repetidas e apara espaços no fim), Aumentar/Diminuir fonte, Copiar tudo, Exportar para arquivo… e Limpar saída.
  • Saídas grandes são limitadas por comando: Configurações → Geral → Tamanho máximo do log por comando.

Outras formas de ver a saída

Terminal interativouma grade de terminal de verdade para vim, htop, less, um Claude Code aninhado. Ligue nas configurações avançadas do comando.
Saída formatadacada linha que é um registro de log JSON (nível, mensagem, timestamp) vira um cartão recolhível com selo de nível; as outras linhas ficam como texto. A busca pode filtrar por nível, e o Kai pode notificar na primeira linha ERROR.

Destacar numa janela

O botão de destacar abre o painel numa janela própria, com as mesmas abas e o mesmo tema, para manter um log longo ao lado do editor. Pelo terminal, kai -gw <caminho> roda um comando e abre a janela dele (veja CLI).
