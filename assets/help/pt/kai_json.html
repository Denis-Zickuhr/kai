Arquivo kai.json (por projeto)

Coloque um kai.json (ou kai.yml/kai.yaml, com os mesmos campos) na raiz do projeto e importe via Arquivo → Importar..., escolhendo "Pasta de projeto...". O Kai cria uma pasta com seus comandos, coleções e variáveis.

Exemplo mínimo

{
  "project_name": "Meu Projeto",
  "env_vars": { "PORT": "8080" },
  "commands": [
    { "name": "Dev Server", "type": "command", "command": "npm run dev", "is_background": true }
  ]
}

Pastas

Coloque um comando ou coleção numa subpasta com folder — use / pra aninhar mais fundo (as subpastas são criadas sob demanda):

{ "name": "Deploy", "type": "command", "folder": "Integrações/Shopee", "command": "./deploy.sh shopee" }

A seção opcional folders só adiciona metadados a essas subpastas (ícone e caminho de CLI), pelo mesmo path:

"folders": [ { "path": "Integrações/Shopee", "icon": "store", "cli_path": "shopee" } ]

Caminhos de CLI

Dê um cli_path a pastas e comandos pra rodá-los pelo terminal. Com o arquivo acima e um comando com "cli_path": "deploy" dentro de Integrações/Shopee, basta rodar kai shopee deploy na pasta do projeto — sem importar nada nem abrir o Kai. Parâmetros obrigatórios viram argumentos posicionais; opcionais, --nome=valor; e o campo description do parâmetro aparece no --help. Detalhes em CLI.

Comando HTTP

{
  "name": "Autenticar",
  "type": "http",
  "http_config": {
    "method": "POST",
    "url": "{{BASE_URL}}/auth/login",
    "headers": { "Content-Type": "application/json" },
    "body": "{\"user\":\"{{USER}}\",\"pass\":\"{{PASS}}\"}",
    "env_extractors": [ { "json_path": "token", "env_var": "AUTH_TOKEN" } ]
  }
}

Cada flag de comando, um exemplo cada

hidden — fica fora da árvore até "Mostrar ocultos" ser ativado:

{ "name": "Utilitário interno", "type": "command", "command": "./helper.sh", "hidden": true }

hide_on_run — esconde a janela do Kai enquanto este comando roda:

{ "name": "Abrir editor", "type": "command", "command": "code .", "hide_on_run": true }

capture_env — captura as variáveis que o comando exporta como variáveis dinâmicas, mas só os nomes listados em declared_env_vars (ex: um login que exporta um token):

{ "name": "gh auth login", "type": "command", "command": "gh auth login", "capture_env": true,
  "declared_env_vars": [ { "name": "GH_TOKEN" } ] }

language / interpreter — o texto do comando é código Python ou Node em vez de uma linha de shell (nunca interpolado: as variáveis chegam como variáveis de ambiente). interpreter sobrepõe o global neste comando. Veja Python e Node:

{ "name": "Relatório", "type": "command", "language": "python",
  "command": "import os\nprint(os.environ['NODE_ENV'])" }
{ "name": "Olá", "type": "command", "language": "node", "interpreter": "~/.nvm/versions/node/v22/bin/node",
  "command": "console.log('olá', process.env.USER)" }

open_last_link — abre a última URL http(s):// impressa na saída quando o comando termina com sucesso:

{ "name": "Subir túnel", "type": "command", "command": "ngrok http 3000", "open_last_link": true }

interactive_terminal — renderiza um terminal de verdade em vez de um log em texto puro, para apps de tela cheia:

{ "name": "htop", "type": "command", "command": "htop", "interactive_terminal": true }

terminal_target — roda o comando através de um perfil de execução nomeado (Configurações → Perfis de Execução), ex: dentro do WSL:

{ "name": "Listar arquivos (WSL)", "type": "command", "command": "ls -la", "terminal_target": "WSL" }

compact_output — colapsa linhas em branco repetidas e apara espaços à direita:

{ "name": "Build verboso", "type": "command", "command": "make -j4", "compact_output": true }

ignore_exit_code — trata o comando sempre como sucesso, para programas que retornam código != 0 mesmo funcionando (ex: explorer.exe do WSL):

{ "name": "Abrir pasta", "type": "command", "command": "explorer.exe .", "ignore_exit_code": true }

auto_run / auto_run_delay_sec — dispara automaticamente quando o Kai inicia:

{ "name": "Iniciar sync em background", "type": "command", "command": "./sync.sh", "is_background": true, "auto_run": true, "auto_run_delay_sec": 5 }

Auto-responsores

Responde um prompt da saída automaticamente (regex → texto enviado ao stdin):

{
  "name": "Resetar BD",
  "type": "command",
  "command": "npm run db:reset",
  "responders": [ { "name": "Confirmar", "pattern": "\\[y/N\\]", "response": "y" } ]
}

Condição de Execução

Só roda quando uma condição passa — aqui, só se TOKEN estiver vazio ou EXPIRES_AT já tiver passado:

{
  "name": "Login",
  "type": "command",
  "command": "gh auth login",
  "execution_conditions": [
    { "name": "Token ausente", "left": "{{TOKEN}}", "op": "not_exists" },
    { "name": "Token expirado", "left": "{{EXPIRES_AT}}", "op": "lt", "right": "{{$timestamp}}" }
  ],
  "condition_combinator": "or"
}

Hooks

Referenciam outros comandos do mesmo arquivo pelo nome — pre/post rodam antes/depois do comando principal, cleanup sempre roda (sucesso, falha, parada manual ou reset):

{
  "name": "Dev Server",
  "type": "command",
  "command": "npm run dev",
  "is_background": true,
  "hooks": { "pre": ["Login"], "post": [], "cleanup": ["Parar túnel"] }
}

Coleções

Uma fonte de dados tabular, versionada junto do projeto, referenciada por um parâmetro select pelo nome:

{
  "commands": [{
    "name": "Saudar", "type": "command", "command": "echo {{cliente.value}}",
    "params": [{ "name": "cliente", "type": "select", "collection": "Clientes", "collection_display_field": "value" }]
  }],
  "collections": [{
    "name": "Clientes",
    "schema": [ { "name": "key", "label": "ID", "type": "key" }, { "name": "value", "label": "Nome", "type": "value" } ],
    "entries": [ { "values": { "key": "1", "value": "Alice" }, "favorite": true } ]
  }]
}

Ainda não tem kai.json?

Ative "Detectar definições genéricas" no diálogo de Importar Projeto — o Kai reconhece package.json, docker-compose.yml, requirements.txt/pyproject.toml/manage.py, composer.json e um Makefile, sugerindo comandos prontos a partir deles.

Referência completa de campos, todos os tipos de parâmetro, e um checklist de geração para modelos de IA: assets/manifesto/kai-json-manifesto.md no repositório.
