Hooks (pre/post/cleanup) & Condição de Execução

Um comando pode disparar outros antes (pre), depois (post), e sempre que termina (cleanup):

[Pre-Hooks]  →  [Comando principal]  →  [Post-Hooks]  →  (sempre) [Cleanup]

Se um pre-hook falhar (exit≠0 ou HTTP≥400), o pipeline aborta e o comando principal nunca roda. Se um post-hook falhar, o pipeline é marcado como sem sucesso. Hooks de cleanup sempre rodam — sucesso, falha, parada manual ou reset.

Caso clássico

Um pre-hook HTTP autentica e extrai o token (Env Extractor) → o comando principal usa {{AUTH_TOKEN}}.

Exemplo de cleanup

Um dev server que também subiu um túnel via pre-hook pode derrubá-lo no cleanup:

- name: "Dev Server"
  type: "command"
  command: "npm run dev"
  is_background: true
  hooks:
    pre:
      - "Subir túnel"
    post: []
    cleanup:
      - "Parar túnel"

Herança por pasta

Comandos de pastas ancestrais aparecem como hooks disponíveis nas subpastas (marcados com ⤴ pasta). Assim um utilitário na raiz serve a todos os comandos abaixo.

Hooks em pastas

Uma pasta também pode ter hooks (editor de pasta → aba Hooks): eles envolvem todo comando daquela pasta e das subpastas, somados aos do próprio comando. O pre roda da pasta mais externa até o comando; post e cleanup desfazem na ordem inversa: os do comando, depois as pastas da mais próxima à mais externa.

Nada é herdado se você não quiser — é preciso dizer: uma subpasta desliga Herdar hooks das pastas acima (ela ignora os hooks das pastas de cima; os dela e os das filhas continuam valendo), e um comando desliga Herdar hooks das pastas na aba Hooks dele (ignora todo hook de pasta). As duas abas listam o que chega de cima, só leitura, com a pasta de origem. Um comando nunca é hook de si mesmo, e um hook repetido roda uma vez por fase. No kai.yml eles se escrevem pelo nome do comando: hooks: no topo do arquivo (o projeto) ou numa entrada de folders:, com inherit_hooks: false / inherit_folder_hooks: false para não herdar.

Condição de Execução

Um comando ou hook também pode ter uma condição de execução — uma guarda que decide se ele roda de verdade, baseada em comparar valores interpolados. Roda só se o token estiver ausente ou expirado:

- name: "Login"
  type: "command"
  command: "gh auth login"
  execution_conditions:
    - name: "Token ausente"
      left: "{{TOKEN}}"
      op: "not_exists"
    - name: "Token expirado"
      left: "{{EXPIRES_AT}}"
      op: "lt"
      right: "{{$timestamp}}"
  condition_combinator: "or"

Operadores: exists, not_exists, eq, ne, gt, ge, lt, le, contains, not_contains. Combine várias condições com E ou OU. Quando a condição não passa, escolha entre pular silenciosamente (ainda conta como sucesso) ou falhar de verdade.
