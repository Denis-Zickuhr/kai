KIP — interfaces de aplicativo para comandos

O KIP (Kai Interface Protocol) permite que um comando transforme o painel de saída em um pequeno aplicativo: em vez de texto, o Kai mostra formulários, confirmações, listas, tabelas, barras de progresso, checklists e um cartão de resultado com botões. O programa só imprime linhas JSON; o Kai desenha a interface.

Serve para assistentes (deploy, restauração, criação de projetos, onboarding), logins que exportam um token, conversão de arquivos e consultas com tabela de resultados.

1. Ativando

Abra o editor do comando, aba KIP (só comandos do tipo comando, não HTTP), e marque Interface KIP (ou use kip: true no arquivo). Abrir em janela própria (kip_window: true) mostra a view em uma janela separada. Fechar a janela ao terminar (kip_auto_close: true, com atraso opcional em segundos) fecha essa janela sozinha depois de uma execução bem-sucedida — feito para scripts rápidos disparados com kai -gw; uma falha ou um cancelamento mantém a janela aberta para você ler o erro.

  • O Kai nunca altera o seu comando. Se a ferramenta precisa de um flag (mytool deploy --kip), escreva-o no comando.
  • O formulário de parâmetros continua rodando antes, e {{VAR}} funciona no comando.
  • O Kai define KIP_VERSION=1 e KIP_LOCALE (en/pt) no ambiente do programa.
  • Segundo plano, terminal interativo, saída formatada, Markdown, execução automática, agendamento, respostas automáticas e exportar do ambiente ficam desativados em comandos KIP, e um comando KIP não pode ser usado como hook.

2. Como o programa fala com o Kai

stdoutmensagens para o Kai, um objeto JSON por linha: {"kip":1,"type":"..."}
stdinrespostas do Kai: response, change, back, cancel
stderrlog livre, exibido em Detalhes → Log

A primeira mensagem deve ser hello. Se o processo terminar (ou passarem 10 segundos) antes dela, o Kai mostra "Este comando não suporta KIP". Linhas do stdout que não são protocolo vão para o log.

hellohandshake; dá nome ao aplicativo
promptformulário com campos; espera a resposta
confirmsim/não (danger para ações destrutivas)
patch / invalidatualiza campos com o formulário aberto / recusa uma resposta com mensagens por campo
message, markdowncartão de status, texto formatado
progress, steps + stepbarra (ou indeterminada), checklist ao vivo
tabletabela somente leitura (selecione uma célula e use Ctrl+C)
notifynotificação do sistema
set_envexporta uma variável declarada
chip_resultandamento e resultado de um chip (veja abaixo)
donetela de resultado com botões: abrir URL (http/https), mostrar no gerenciador de arquivos, copiar

3. Tipos de campo

text, secret, textarea, number, date, select, list, table, filepick, folderpick e flags. Os campos podem ser required, ter default, pertencer a um group e ser observados (watch): quando o usuário muda um campo observado o Kai envia change e o programa responde com um patch (é assim que uma segunda lista depende da primeira). O Kai lembra as últimas respostas de cada prompt (nunca de secret); desligue com remember: false.

4. Chips e listas longas

Chips são botões pequenos sob os campos de um prompt para ações efêmeras — "mostrar o contexto desta branch", "sincronizar", "apagar". Clicar não responde o formulário: o Kai envia chip ao programa, que responde com mensagens chip_result (running e depois success ou error, com um text em Markdown) exibidas numa caixa sob os chips. O passo continua aberto e um erro nunca encerra a sessão.

  • Um chip pode pedir confirmação antes (confirm, dentro da caixa) e ter visual destrutivo (danger).
  • requires mantém o chip desabilitado até os campos listados estarem preenchidos.
  • Um chip roda por vez; feche a caixa no botão ×.

Nos campos list e table, searchable força (ou esconde) a caixa de filtro e page_size divide os itens em páginas, com a barra "Página 2 de 5". As páginas valem para o resultado filtrado e mantêm a sua seleção.

5. O auxiliar kai kip

Em scripts shell você não precisa escrever JSON à mão:

kai kip hello --title "Deploy"
kai kip prompt --id env --title "Para onde?" \
  --field select env "Ambiente" --options dev,staging,prod --required
read -r resp
[ "$(kai kip get "$resp" type)" = cancel ] && exit 130
env=$(kai kip get "$resp" values.env)
kai kip progress 50 "Enviando..."
kai kip done --title "Publicado" --action open_url:"Abrir":https://example.com

Ele apenas imprime mensagens e lê valores: não precisa do app aberto. kai kip --help lista todos os verbos e opções.

Python, Node e PHP, sem arquivo: troque a Linguagem do comando para Python, Node ou PHP e ligue o KIP — o texto do comando é o programa, e o Kai injeta um módulo kip (import kip no Python; o global kip no Node, com await no topo; a classe Kip no PHP):

import kip
v = kip.prompt([{"name": "env", "type": "select", "options": ["dev", "prod"]}],
               id="where", title="Para onde?")
kip.progress(50, "Publicando...")
kip.done(title="Publicado em " + v["env"])
$v = Kip::prompt([['name' => 'env', 'type' => 'select', 'options' => ['dev', 'prod']]],
                 ['id' => 'where', 'title' => 'Para onde?']);
Kip::progress(50, 'Publicando...');
Kip::done('Publicado em ' . $v['env']);

O hello é enviado por você, a saída é sem buffer, Cancelar encerra com código 130 e Voltar levanta kip.Back (KipBack no PHP). O {{VAR}} não é substituído neste código; as variáveis vêm de os.environ / process.env / getenv(). Seus próprios arquivos de script (python3 tool.py num comando Nativo com KIP ligado) também acham o módulo — veja Linguagens.

5b. kip no shell

Ligue o KIP num comando Nativo que roda num shell POSIX (Linux, macOS, WSL, outros perfis POSIX): o Kai define uma função kip com os mesmos verbos do kai kip — sem precisar do binário kai, então funciona no WSL, em containers e no SSH. O hello é enviado por você e o {{VAR}} é substituído como em qualquer comando nativo.

kip prompt --id where --title "Para onde?" --field select env Ambiente --options dev,staging,prod --required
kip recv                          # a resposta cai em $KIP_MSG (Cancelar sai com 130)
alvo=$(kip get "$KIP_MSG" values.env)
kip progress 50 "Publicando..."
kip done --title "Publicado em $alvo"

Limites:

  • O auxiliar é sh POSIX + awk (mawk, gawk e busybox funcionam); a forma inline também precisa de base64 e gzip. Sem jq.
  • Use o kip recv no script principal, não dentro de $( ), senão a resposta se perde com o subshell; não reutilize os nomes _kip_*.
  • O kip raw só confere o formato básico da mensagem; o kip get imprime números com expoente como foram escritos e descarta bytes NUL. As mensagens do auxiliar são em inglês.
  • No Windows sem perfil POSIX (cmd.exe / PowerShell puros) não há a função kip: use um perfil WSL, ou escreva o programa em Python, Node ou PHP. Um texto longo demais para a linha de comando o Kai grava num arquivo próprio e carrega de lá (shell, Python, Node e PHP).

6. Exportando variáveis

Um programa só pode definir uma variável dinâmica com set_env para nomes listados na aba Variáveis exportáveis do comando. O valor fica disponível na hora para outros comandos como {{NOME}}.

7. A view

  • Uma tela por vez, com um resumo das respostas anteriores acima (segredos aparecem como ••••).
  • Voltar aparece quando o programa permite; Cancelar execução pede ao programa que pare (e o encerra após 3 segundos).
  • Uma confirmação destrutiva dá foco ao botão de recusa, então o Enter nunca confirma sem querer.
  • Detalhes (recolhido): o Log e o inspetor de Protocolo com todas as mensagens nos dois sentidos.
  • A barra de abas do painel de saída fica oculta em comandos KIP; o ícone no canto superior direito da view abre a janela própria.
  • Falhas, cancelamento, comando sem suporte e erros de protocolo mostram um cartão com os detalhes abertos e Executar de novo.

8. Configurações e o manifesto de criação

Em Configurações → KIP ficam as preferências globais: quanto esperar a primeira mensagem do programa, a resposta a uma atualização de campo e o tempo depois de Cancelar; se as últimas respostas são lembradas; e se o Detalhes abre sozinho nas falhas; e o Tamanho da janela própria — seguir a configuração geral, janela normal, maximizada ou tela cheia (vale só para views KIP). Se um comando usa KIP é definido no editor dele (só comandos do tipo comando, não HTTP).

Ajuda → Manifesto de criação copia, com um clique, o guia para entregar a um assistente de IA escrever um programa KIP (ou um kai.yml) para você.

9. No terminal

kai -g <comando> executa um comando KIP no app e traz a view para a frente. Com -w (ou kip_window) a view abre em janela própria e a janela principal não é mostrada. No modo local (kai dentro de uma pasta com kai.yml) comandos KIP são recusados: não há interface para desenhá-los.
