Commands

A Command runs a program on your machine. The text is a line (or script) for your shell — Native, the default — or code in Python, Node or PHP (see Python, Node & PHP). HTTP requests have their own type: HTTP Commands.

How to create

Menu Item → New Command (or Ctrl+N), Command tab. Fill in the command and, optionally, the working directory.

npm run dev

Working directory

By default the command inherits the working directory of its folder (for an imported project, the project root). Pick Custom directory for its own — a relative path is resolved over the inherited one — or None to cut the inheritance and run in the target's default directory. {{PROJECT_PATH}} is the root of the nearest project folder: {{PROJECT_PATH}}/api.

Variables

Use {{VAR}} to interpolate variables from the active environment:

echo "Starting on port {{PORT}} ({{NODE_ENV}})"

Precedence: Global < Folder/Project < Dynamic < Parameters. See Variables, and Parameters to ask for values before running. (In Python/Node code {{VAR}} is not replaced: variables are environment variables.)

Background

Check Run in background for long-running processes (e.g. a dev server). Kai keeps the process alive and shows its status; stop it whenever you want (SIGTERM, then SIGKILL after the grace period, applied to the whole process group). See Processes.

Interactive commands using read accept input directly in the output panel's input field.

Interactive terminal (advanced settings)

For full-screen apps that draw with a cursor — vim, htop, less, a nested Claude Code — turn on Interactive terminal (TUI). The output becomes a real terminal grid instead of a plain-text log:

htop

Ignore exit code (advanced settings)

Some tools return a non-zero exit code even when they worked fine — the classic case is explorer.exe called from WSL. Turn on Ignore exit code and Kai always treats the command as a success; a real crash (signal/segfault) is still reported:

explorer.exe .

Other options (advanced settings)

  • Hide Kai while running — for a command that opens another window, e.g. code ..
  • Open last printed link when finished — opens the last http(s) URL the command printed (a dev server, a tunnel).
  • Formatted output — see The Output panel.
  • Export variables — after a native command runs, the names you list under Exportable variables are captured as dynamic variables (a login that exports a token, for instance). Only declared names are ever read.
  • Run on a schedule / when Kai starts — see Schedules & auto-run.
  • Auto-replies — see Auto-replies.

Terminal targets (WSL, containers, ...)

Pick a Profile to run the command through a wrapper — see Terminals & WSL.
