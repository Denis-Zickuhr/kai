Folders, tree & search

Folders and commands

Commands live inside folders. Each top-level folder becomes a tab; subfolders nest inside it. Create things from the Item menu, the side bar or the right-click menu: New Folder, New Command, New Collection (see Collections).

A folder can carry its own settings: name, icon, parent folder, the execution profile its commands inherit, its own variables and a CLI path. A folder also has a working directory, inherited by its subfolders and commands: each one can inherit it, set its own (a relative path is resolved over the inherited one) or choose None to cut the inheritance. A project imported from a kai.yml becomes a project folder whose working directory is the project root; {{PROJECT_PATH}} is always the root of the nearest project folder.

Syncing a project folder with its file

A project folder can be kept in step with a kai.yml in its working directory, by hand: right-click the folder and choose Sync Kai → File or Sync File → Kai. Nothing runs on its own.

  • Kai → File writes the folder's subfolders and commands to the file. The file is always kai.yml (a kai.json is neither read nor touched). It is written by path and name, without ids: loading it keeps the id, remembered values and links of whatever stays in place with the same name (renaming makes a new item). Variables marked Secret are written by name only — their value stays in your Kai.
  • File → Kai replaces everything inside the folder with the file's content (the folder itself stays).
  • After each sync Kai remembers what both sides looked like. If the side that would be overwritten changed since then — or was never synced — you're asked to confirm first, with the counts of what would be replaced.
  • File → Kai reads both a hand-written project file (the kai.yml format: folder paths, hooks by name, no ids) and the format Kai → File writes. It never modifies the file. Kai → File also writes the folder's variables and folder actions (with expansion and groups) — global actions stay in Settings. Collections are never written: a select parameter keeps only the collection's name as a reference, matched by name with your collections when the file is loaded (not found = reported, the parameter is left without a source). An action pointing to a command outside the project is written by its name. Remembered parameter values never go. Collections defined inside a file are not imported by the sync and are reported as skipped.
  • Kai → File always writes Kai's own export format, so over a hand-written file it asks first and replaces it.
  • Out-of-sync mark: a project folder that has been synced before gets an amber dot on its icon (with a tooltip saying what changed) when Kai changed and the file doesn't have it yet, when the file changed (or disappeared) and Kai doesn't have it, or both. Kai checks when it opens, when the window regains focus, after you save changes and after a sync — it doesn't watch the file. Running a command (remembered parameter values) doesn't count as a change. A folder that was never synced isn't marked.

Folder actions

An action is an existing command mapped to appear as an icon on a folder's row — handy for git fetch, pull or status, which you want to run on this folder.

  • Per folder: edit the folder → Actions tab, which works like the dynamic parameters: Add action and the count outside the table, a table with just the names (drag to reorder, pencil to edit, trash to remove) and a small form to pick the command. They show left to right, in registration order, at the end of the row, after the time marker.
  • For every folder: Settings → Actions, each one optionally limited to project folders. Global ones come first, then the folder's own.
  • Actions appear on subfolders; a top-level folder is a tab and has no row.
  • Expansion actions: in the action's form, turn on Expansion action for the useful-but-not-so-much ones. Instead of an icon, they stay hidden behind a single expand symbol (chevron) at the end of the row; clicking it opens a menu with them. They behave exactly like the others (click runs, loads or shows the output; right-click for the same menu) — they just live somewhere else.
  • Groups: type a Group in the action's form (a theme, like “Git” or “Docker”) and, optionally, pick a group icon (without one, a default is used). Actions of the same group share one icon on the row that opens a menu with them. A group is one thing across global and folder actions (same name, any capitalization), and its icon applies to all its actions. An action in a group doesn't need the expansion flag — the group is its place. Order on the row: plain icons, then one icon per group, then the expand symbol.
  • Click an icon: if the action never ran, it runs; if it already ran and isn't loaded, the click loads its saved output; with the output loaded, hovering shows a play glyph and the click runs it again. Whenever the click will only show an output (running, or it ran and isn't loaded yet), hovering shows an eye instead, so it is clear nothing will execute. While running, a click just shows the output. It runs with that folder as context: the working directory becomes the folder's, and the folder's variables and terminal profile apply. A command with parameters asks for them as usual; KIP commands work as actions too and show their KIP interface in the output panel.
  • The icon is green while it runs on that folder, accent when idle. The same action can run on several folders at the same time, each with its own output.
  • The output opens in the output panel and the icon is focused; it's kept in memory per action and folder. Click elsewhere on the same row to unfocus — the saved output stays.
  • Folder exports carry actions by command name; Global actions is its own item in the global export/import, matched by unique command name on import. If the actions use commands that live outside the exported folder, Folder actions (on by default) carries those commands too: on import, the ones you don't have yet go into an Imported actions folder and the actions get linked to them; a command you already have with the same name is reused, not copied.

Folder documentation

Select a folder and the Output area shows its documentation: the README.md in the folder's working directory opens by itself, with nothing to configure. Without a README, the first document found there opens instead; in a folder with no documents at all, a button in the middle creates the README.md. The tree of files and notes starts collapsed — open it with the first button on the top bar.

  • Links: a relative link to another .md opens it right there; the bar on top has back / forward, the clickable path and a button for the tree of the folder's documents. The zoom stays on that bar.
  • Kai links redirect to Kai itself: [Start](kai:run/Dev server) runs a command (after asking you), kai:open/Name selects a command or folder and kai:env/Name switches the environment (also after asking). A name with spaces works as is.
  • Diagrams: a ```mermaid block with a graph TD / flowchart LR is drawn as a diagram; other diagram types stay as code.

Files, editing and notes in the documentation

  • File explorer: the side panel opens by itself when the folder has other files. Search by name, the funnel chooses the file types shown (default: .md, .txt and files without extension; the menu lists the extensions found), and the file-plus button creates a new file in the selected folder.
  • Editing: the pencil next to the magnifier turns the viewer into an editor with syntax colors, line numbers, auto-indent and live validation for JSON, YAML and XML. Save (Ctrl+S) and Discard sit next to it; leaving the file with unsaved changes asks first.
  • Editor shortcuts (VS Code style): Alt+↑/↓ move lines, Shift+Alt+↑/↓ copy them, Ctrl+Shift+K delete, Ctrl+Enter new line below, Ctrl+L select line, Ctrl+/ comment, Ctrl+D add the next occurrence to the selection (multi-cursor), Ctrl+Shift+L select all occurrences, Ctrl+Alt+↑/↓ or Alt+click add a cursor, Shift+Alt+drag column selection, Esc back to one cursor, Ctrl+Shift+\\ matching bracket, Ctrl+G go to line, Shift+Alt+F format, Ctrl+H replace. Brackets and quotes close themselves.
  • Tools (wand): format, minify, sort keys, escape, validate, convert JSON ⇄ YAML/XML, Base64/URL, sort lines, remove duplicates, case. They act on the selection, or on the whole text.
  • Notes: New Note (right-click menu) creates quick text kept inside Kai — a Markdown, text, JSON, YAML or XML note — shown in the tree with a notebook icon and in a Notes section below the files of the folder. A note is local by default (only this Kai); turn that off in Note Properties and it travels with exports and the project file (notes: in kai.yml).
  • A hidden command run by schedule, auto-run or kai run runs quietly: it does not open the output nor create a tab. Click it (with hidden items shown) and you see its output as usual.

The right-click menu

On a command: Edit, Duplicate, Export…, Delete (Export… opens the export dialog already pointing at that item). On a folder: the same, plus Hide / Show Folder (and, on a project folder, the sync actions above). The same menu opens from the keyboard (Ins by default). Run, Stop (terminate), Force stop and Reset and restart are in the action side bar.

Search

Ctrl+F shows the search bar; it filters commands by name with a fuzzy match (typos and gaps are fine). Press it again to hide. Searching opens the folders that hold a match; when you stop searching, every folder goes back to how it was before (no tree left wide open).

Order, hiding and filtering

  • Order: the command editor has an Order field. Lower numbers come first; automatic sorts by name.
  • Hide: hidden items leave the tree until Show hidden items is on. Hide a command from its editor or a folder from the menu.
  • Show only running commands: a quick filter for what is running right now. Root folders (tabs) with nothing running disappear while it is on, and folders go back as they were when you turn it off.
  • Expand / collapse the selected folder or everything.

Editing

  • Every editor has a Simple and an Advanced (JSON) mode; Ctrl+E switches an open editor.
  • Edit body (quick) in the side bar opens just the body of an HTTP command.
  • Icons come from the built-in set or any image file you pick.
  • Duplicate copies a command, a folder or a collection.
Every action here has a keyboard shortcut you can change — see Keyboard shortcuts. Settings → Storage lists, duplicates and deletes many items at once.
