Hooks (pre/post/cleanup) & Execution Conditions

A command can trigger others before (pre), after (post), and whenever it finishes (cleanup):

[Pre-Hooks]  →  [Main command]  →  [Post-Hooks]  →  (always) [Cleanup]

If a pre-hook fails (exit≠0 or HTTP≥400), the pipeline aborts and the main command never runs. If a post-hook fails, the pipeline is marked unsuccessful. Cleanup hooks always run — success, failure, manual stop, or reset.

Classic case

An HTTP pre-hook authenticates and extracts the token (Env Extractor) → the main command uses {{AUTH_TOKEN}}.

Cleanup example

A dev server that also started a tunnel via a pre-hook can tear it down on cleanup:

{
  "name": "Dev Server",
  "type": "shell",
  "command": "npm run dev",
  "is_background": true,
  "hooks": { "pre": ["Start tunnel"], "post": [], "cleanup": ["Stop tunnel"] }
}

Folder inheritance

Commands from ancestor folders appear as available hooks in subfolders (marked with ⤴ folder). This way a utility at the root serves all commands below it.

Execution conditions

A command or hook can also carry an execution condition — a guard deciding whether it actually runs, based on comparing interpolated values. Runs only if the token is missing or expired:

{
  "name": "Login",
  "type": "shell",
  "command": "gh auth login",
  "execution_conditions": [
    { "name": "Token missing", "left": "{{TOKEN}}", "op": "not_exists" },
    { "name": "Token expired", "left": "{{EXPIRES_AT}}", "op": "lt", "right": "{{$timestamp}}" }
  ],
  "condition_combinator": "or"
}

Operators: exists, not_exists, eq, ne, gt, ge, lt, le, contains, not_contains. Combine multiple conditions with AND or OR. When a guard doesn't pass, choose whether that's a silent skip (still a success) or a real failure.
