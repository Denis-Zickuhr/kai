Comandos

Um Comando roda um programa na sua máquina. O texto é uma linha (ou script) para o seu shell — Nativa, o padrão — ou código em Python ou Node (veja Python e Node). Requisições HTTP têm tipo próprio: Comandos HTTP.

Como criar

Menu Item → Novo Comando (ou Ctrl+N), aba Comando. Preencha o comando e, opcionalmente, o diretório de trabalho.

npm run dev

Diretório de trabalho

Vazio usa o padrão de onde o comando roda. {{PROJECT_PATH}} é a raiz de um projeto importado: {{PROJECT_PATH}}/api.

Variáveis

Use {{VAR}} para interpolar variáveis do ambiente ativo:

echo "Subindo na porta {{PORT}} ({{NODE_ENV}})"

Precedência: Global < Pasta/Projeto < Dinâmica < Parâmetros. Veja Variáveis e Parâmetros para pedir valores antes de rodar. (Em código Python/Node o {{VAR}} não é substituído: as variáveis são variáveis de ambiente.)

Background

Marque Executar em background para processos longos (ex.: um dev server). O Kai mantém o processo vivo e mostra o status; pare quando quiser (SIGTERM e, depois do prazo de graça, SIGKILL, aplicados ao grupo de processos inteiro). Veja Processos.

Comandos interativos com read aceitam entrada direto no campo de entrada do painel de saída.

Terminal interativo (configurações avançadas)

Para apps de tela cheia que desenham via cursor — vim, htop, less, um Claude Code aninhado — ative Terminal interativo (TUI). A saída vira uma grade de terminal de verdade em vez de um log em texto puro:

htop

Ignorar código de saída (configurações avançadas)

Alguns programas retornam um código de saída diferente de zero mesmo funcionando — o caso clássico é o explorer.exe chamado do WSL. Ative Ignorar código de saída e o Kai sempre trata o comando como sucesso; um crash de verdade (sinal/segfault) continua sendo reportado:

explorer.exe .

Outras opções (configurações avançadas)

  • Ocultar o Kai ao executar — para um comando que abre outra janela, ex.: code ..
  • Abrir o último link impresso ao terminar — abre a última URL http(s) que o comando imprimiu (um dev server, um túnel).
  • Saída formatada e Renderizar como Markdown — veja O painel de Saída.
  • Exportar variáveis — depois que um comando nativo roda, os nomes listados em Variáveis exportáveis são capturados como variáveis dinâmicas (um login que exporta um token, por exemplo). Só os nomes declarados são lidos.
  • Agendar / rodar ao iniciar o Kai — veja Agendamentos e auto-run.
  • Auto-respostas — veja Auto-respostas.

Alvos de terminal (WSL, containers, ...)

Escolha um Perfil para rodar o comando através de um wrapper — veja Terminais e WSL.
